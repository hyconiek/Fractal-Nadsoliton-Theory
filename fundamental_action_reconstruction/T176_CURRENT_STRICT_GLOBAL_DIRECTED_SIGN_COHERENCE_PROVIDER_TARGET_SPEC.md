# T176 Current Strict Global Directed Sign-Coherence Provider Target Spec

Status: `T176_CURRENT_STRICT_GLOBAL_DIRECTED_SIGN_COHERENCE_PROVIDER_TARGET_SPEC_NO_FALSE_PASS`
As of: `2026-03-17`

## Goal

After `P711/N707`, the current strongest honest reading is:

1. the previous `sigma_int` / topological methodology survives as a strict **local** ingredient class,
2. projective strict-core selector closure is already exported globally,
3. but the repo still lacks the missing **global** provider taking those ingredients to chartwise directed-sign coherence on the full `C_v1` atlas.

`T176` exists to name that exact missing object.

This target is narrower than “solve everything under `T173`” and more honest than pretending the existing local/provider ingredients already close the global branch.

## Scope

`T176` is scoped to one strict-core target only:

```text
an explicit global directed-sign coherence provider on the full chart atlas C_v1
```

The target object must:

1. live on the full exported `C_v1` atlas,
2. be sourced from exported strict-core objects only,
3. determine chartwise directed-sign coherence without importing free convention data
   (`t_i`, `s_ij`, marked generator/orientation token, hidden chart selector slots),
4. stay below any ToE closure claim.

`T176` is **above**:

- the local `sigma_int -> theta` bridge in declared `R1` scope,
- projective closure,
- convention-layer chart sign fixing (`T175`),
- convention-layer oriented edge sign lift (`T174`).

## Target object

An honest discharge of `T176` must export one object of the form:

```text
GlobalDirectedSignCoherenceProvider_global_C_v1_strict_core_v1
```

with typed meaning:

```text
exported strict-core local/provider ingredients
  -> chartwise directed representative coherence on all charts of C_v1
```

and with explicit evidence that the resulting coherence is not merely:

1. a convention-layer 0-cochain sign fix,
2. a convention-layer 1-cochain oriented edge lift,
3. a re-labeling of premise-based directed data already tracked outside strict core.

## Acceptance tests (no false pass)

Any discharge of `T176` must satisfy all of:

1. **Global scope:** the provider acts on the full exported chart atlas on `C_v1`, not only on `R1`, `pair1/pair2`, or one rooted corridor.
2. **Strict-core provenance:** no added `strict_convention` sign data may be smuggled in as the effective source.
3. **Directed coherence:** the provider must remove the current global directed-sign coherence gap, not only preserve projective/ray data.
4. **No hidden selector slots:** no free chartwise or edgewise sign parameters, no hidden retuning, no external orientation token.
5. **Hard-limit discipline:** if kernel-alone/global `QW-2191` still remains open, that must be stated explicitly; if it is claimed discharged, that requires a separate theorem-level statement.

## What `T176` does not require

`T176` does **not** require, by itself:

1. Standard Model identification,
2. a strict physical-unit calibration map,
3. actual emergent observer closure,
4. ToE closure.

## Hard limits

`T176` must not be satisfied by:

1. `T174`-type oriented edge sign-lift data alone,
2. `T175`-type chart sign-fixing data alone,
3. any object explicitly labeled as `strict_convention`,
4. any object whose only stable content is projective/ray-level.
