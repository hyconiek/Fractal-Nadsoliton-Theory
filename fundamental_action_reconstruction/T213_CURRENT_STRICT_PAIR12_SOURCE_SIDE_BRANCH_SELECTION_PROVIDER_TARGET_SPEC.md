# T213 Current Strict `pair1/pair2` Source-Side Branch-Selection Provider Target Spec

Status: `T213_CURRENT_STRICT_PAIR12_SOURCE_SIDE_BRANCH_SELECTION_PROVIDER_TARGET_SPEC_NO_FALSE_PASS`
As of: `2026-03-18`

## Goal

After `P758/N754`, the current repo already knows something sharper than
before:

```text
the currently exported continuation family out of the surviving P731 witness
split may no longer count as the active primary T173 move
```

So the next honest question is no longer:

```text
can one more continuation inside the already exported P731 -> P747 family still
be stretched into strict progress?
```

It is narrower:

```text
if strict continuation stays on the active T173 provider-shift branch at all,
what exact future-only provider object must an honest next move now aim to
export?
```

`T213` freezes only that target.

It does **not** claim:

1. actual pair1/pair2 branch selection,
2. actual typed promotion bridge out of `P731`,
3. actual `T176` discharge,
4. actual directed/sign-sensitive physical orientation datum in strict core,
5. kernel-alone/global `QW-2191` discharge,
6. ToE closure.

## Reused support

`T213` may reuse only already exported current-state material:

4. `T173`

     no silent kernel-alone `QW-2191` discharge and no silent directed

## Exact target to freeze

Freeze one future-only target:

```text
W_strict_t173_pair12_source_side_branch_selection_provider_target_v1 :
  tau_src_candidate_v1 -> strict_t173_pair12_source_side_branch_selection_provider_target_v1
```

## Why this is the correct next move

Without `T213`, the frontier can still be misread in two false ways:

1. as if “provider shift” already meant some concrete next provider object is
   understood well enough to attack directly,
2. as if the repo could continue honestly without naming the exact future-only
   object shape demanded by `P758/N754`.

`T213` prevents both errors.

It does not solve the frontier.
It only sharpens it.
