# T27 Current Strict Source Orientation Seed Object Support Incompatibility Boundary Spec

Status: `T27_PACKET_READY_CURRENT_STRICT_SOURCE_ORIENTATION_SEED_OBJECT_SUPPORT_INCOMPATIBILITY_BOUNDARY_SPEC_NO_FALSE_PASS`
As of: `2026-03-09`

## Goal

After `N288`, the first `T26` component already has:

1. narrow derivative support,
2. branch-polarity support,
3. one-sided local descent support,
4. chart-independent projection support onto the already actual basis-free
   source-topology layer.

So the strongest honest next question is no longer:

```text
can the same exported material be lifted once more positively
to actual chart-independent seed-object support?
```

It is narrower:

```text
has component 1 now reached a current-state incompatibility boundary
between chart-independent projection support
and actual chart-independent seed-object support?
```

`T27` does not discharge component 1.

It does something narrower:

1. writes one packet-ready incompatibility-boundary spec for the missing
   seed-object support layer,
2. keeps the boundary scoped only to current repo state and current exported
   source-side material,
3. keeps open the possibility of a future new object carrier, new pair-indexed
   provider, or different blocker-cut.

## Formal target

```text
T27_CurrentStrictSourceOrientationSeedObjectSupport_IncompatibilityBoundary

Assume:
  A1. `T26/N284` still keep component 1 as the future-only target
      `strict_source_orientation_seed_target_v1`;
  A2. `N285/N286/N287` already export actual local source-side support through
      derivative datum, branch polarity, and one-sided descent;
  A3. `N288` already exports one actual chart-independent projection support
      packet for that same component;
  A4. the chart-independent layer reached in `N288` is still the already
      exported basis-free source-topology class layer from `N256/N257/N258`;
  A5. no actual chart-independent source-seed object carrier is exported on
      the current repo state;
  A6. no actual pair-indexed seed carrier is exported on the current repo
      state;
  A7. no actual theta values, populated basis-pair instance, `E_orient`,
      admissible `S_sel_int`, or closure datum is exported from this route.

Then:
  C1. component 1 admits one current-state incompatibility-boundary theorem
      between chart-independent projection support and actual chart-independent
      seed-object support;
  C2. another positive lift using only the same current exported material is
      not the honest next move for component 1;
  C3. this boundary remains weaker than impossibility in principle and may be
      reopened by one genuinely new object carrier, one pair-indexed provider,
      or one different blocker-cut.
```

## Meaning of the theorem

If later discharged, `T27` would establish only:

1. the first `T26` component is no longer merely local, but still stops at
   chart-independent projection support,
2. the exact missing layer is object-level rather than class-level,
3. the exact missing layer is also pair-indexed rather than only
   basis-free-class-level,
4. another same-material positive lift would overclaim the current repo state.

It would not establish:

1. discharge of `strict_source_orientation_seed_target_v1`,
2. actual chart-independent seed object,
3. actual pair-indexed seed object,
4. actual theta values,
5. actual populated basis-pair instance,
6. actual `E_orient`,
7. admissible `S_sel_int`,
8. strict-core selector closure,
9. ToE closure,
10. impossibility of all future component-1 routes.

## Acceptance skeleton

This spec is acceptable only if all of the following stay explicit:

1. the boundary is current-state only,
2. `N288` remains valid and is not weakened,
3. class-level basis-free support is not silently relabeled as object-level
   support,
4. pair-indexing is not silently presumed,
5. no seed-object discharge is claimed,
6. no closure claim is introduced.

## Recommended next move

The correct next move is:

1. package one actual incompatibility-boundary packet for the missing
   seed-object support layer of component 1,
2. test whether the current repo really exports that packet,
3. stop the same-material positive lifting there unless one genuinely new
   object carrier, one pair-indexed provider, or one different blocker-cut is
   added.
