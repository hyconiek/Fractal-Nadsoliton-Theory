# T00 Sandbox Strict-Core Ingredient Attempt Scope

Status: `T00_SANDBOX_STRICT_CORE_INGREDIENT_ATTEMPT_SCOPE_NO_FALSE_PASS`
As of: `2026-03-09`

## Goal

The sandbox asks one narrow question:

```text
can we write one truly new strict-core ingredient candidate
without extending the current strict_extension_only ladder
and without pretending that strict-core discharge already exists?
```

## Sandbox-only rule

This attempt must remain removable and non-authoritative.

Therefore:

1. it may introduce new sandbox-only candidate symbols,
2. it may package one new strict-core construction attempt,
3. it may diagnose that attempt against the `F29` admission contract,
4. it may not be counted as official repo export,
5. it may not be used as evidence of strict-core selector closure.

## Construction policy

The sandbox candidate should be stronger than a pure extension lift.

So the candidate must try to localize, inside one new object, explicit slots
for the missing strict-core axes from `F29`:

1. internal orientation,
2. bridge,
3. selector reduction,
4. downstream operator reachability.

At the same time, the candidate must remain:

1. kernel-split-safe,
2. non-substitutive with respect to `K_legacy_ont` / `K_strict_gate`,
3. below actual `E_orient`,
4. below strict-core selector closure,
5. below ToE closure.

## Success criterion inside sandbox

The sandbox counts as useful only if it achieves all of the following:

1. defines one explicit new strict-core candidate object,
2. shows exactly which `F29` axes that candidate does and does not satisfy,
3. keeps all non-satisfied axes explicit,
4. does not launder extension-only acceptance into strict core.

## Failure criterion inside sandbox

The sandbox should be abandoned if it collapses into one of the following:

1. merely renaming the old extension ladder,
2. silently importing `tau_src_candidate_v1` as if it were `S_sel_int`,
3. treating a placeholder slot as an actual discharge,
4. requiring too much cleanup to remove.
